## Agent 的运行机制：PPAF 循环

在当前基于 Transformer 和自回归的 LLM 架构下，模型的原始输出本质上是随机且无序的。而 Harness Engineering 的作用，正是**通过有序的约束驾驭无序的算力**。

一个完备的 Agent 系统，其核心运行机制可以抽象为一个持续循环的四阶段过程：

| 环节 | 英文 | 核心内容 |
| --- | --- | --- |
| **感知** | Perception | Agent 通过「传感器」或接口，从外部环境和内部状态采集信息：用户指令、API 返回、监控指标、历史对话等。感知的全面性与结构化程度直接决定决策上限 |
| **规划** | Planning | 由 LLM 担当的「大脑」理解当前状态与目标的差距，把复杂任务分解为可执行的子任务，涉及路径选择、资源分配、工具筛选与风险预判 |
| **行动** | Action | 通过「效应器」与外部世界互动：调用 API、执行代码、返回信息或与其他系统交互 |
| **反思** | Feedback / Reflection | 行动结果作为反馈被捕获，Agent 比较结果与预期的差异，或触发重新规划，或存入记忆影响下一轮感知 |

## 四大工程维度

Harness Engineering 将工程化体系解构为四个核心维度，每个维度都与 PPAF 闭环的一个或多个环节耦合：

| 工程维度 | 核心隐喻 | 工程目标 | 支撑环节 |
| --- | --- | --- | --- |
| **造缰** | 定义接口、协议与约束 | 为感知和行动提供清晰、稳定、安全的边界与输入输出通道 | 感知 |
| **驭马** | 实现策略、调度与执行控制 | 设计并实现核心决策与执行逻辑，确保 Agent 自主高效地完成任务 | 规划 + 行动 |
| **相马** | 建立评估、观测与选择机制 | 建立度量和评估体系，观测 Agent 的能力、性能与行为 | 反思 |
| **育马** | 构建训练、迭代与记忆体系 | 设计数据回流、模型训练和知识更新的闭环，让 Agent 从经验中学习 | 反思 + 记忆 |

## 一个战略分析矩阵

把不同类型的 Agent 应用放到两个维度上看，能更清楚地理解 Harness 的价值：

- **横轴：认知循环**——从「被动响应」（单次触发、预定义任务）到「主动规划与反思」（长期目标、多步规划、动态调整）
- **纵轴：上下文效率**——从「低效」（人工投喂上下文）到「高效」（沙盒化、系统级自动注入）

| | 主动规划与反思 | 被动响应 |
| --- | --- | --- |
| **高上下文效率** | **自主智能体**：自动化代码生成与修复、无人值守实验平台、自主交易系统 | **专家辅助系统**：IDE Copilot、对话式 BI、交互式设计工具 |
| **低上下文效率** | **高阶流程自动化**：自然语言 CLI 工具、多步 API 封装、信息查询机器人 | **基础问答与单点工具**：客服机器人、天气查询 |

这个矩阵揭示了 Harness Engineering 的价值所在：**Harness 的成熟度，直接决定了 Agent 应用能否从低效、被动的象限，跃迁至高效、主动的象限。**

## 小结

PPAF 循环是 Agent 的「心跳」，四大维度是套在它身上的「马具」。下一篇进入设计层面：如何用一个 REPL 容器的抽象，把这套循环工程化地实现出来。
